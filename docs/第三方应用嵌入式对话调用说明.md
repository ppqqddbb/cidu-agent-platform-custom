# 第三方应用嵌入式对话调用说明

## 1. 适用范围

本文用于第三方业务系统通过 `embed.min.js` 嵌入 Dify 对话窗口时的接入说明。

当前已支持：

- 按第三方用户 `user_id` 做会话隔离
- 允许在固定会话能力下新建对话
- 左侧展示历史对话列表
- 内置窗口拖拽、缩放
- 向 Agent / Workflow 透传第三方 `context_token`

适用仓库：

- `D:\workspace\code\dify`

---

## 2. 第三方最少需要传什么

业务系统最少传这两个值：

- `systemVariables.user_id`
  用于按第三方用户隔离历史会话
- `inputs.context_token`
  用于 Agent 工具调用第三方接口时做鉴权

建议同时开启：

- `allowNewChat: true`
  允许用户在嵌入窗口中主动新建对话

---

## 3. 推荐嵌入方式

```html
<script>
  const thirdUserId = 'user_10086'
  const contextToken = 'YOUR_CONTEXT_TOKEN'

  window.difyChatbotConfig = {
    token: 'YOUR_DIFY_APP_TOKEN',
    baseUrl: 'http://localhost',

    // 推荐：clean 模式使用内嵌聊天布局
    embedLayout: 'clean',

    // 推荐：即使存在固定 conversation_id，也允许新建对话
    allowNewChat: true,

    // 推荐：桌面端支持拖拽和缩放
    windowDraggable: true,
    windowResizable: true,

    inputs: {
      // 透传给工作流 / Agent / 工具
      context_token: contextToken,
      integration_id: 'third-system-a',
    },

    systemVariables: {
      // 会话隔离主键
      user_id: thirdUserId,

      // 可选：如果需要打开指定会话可传
      // conversation_id: '00000000-0000-0000-0000-000000000000',
    },

    userVariables: {
      // 可选：仅用于前端展示
      name: '张三',
      avatar_url: '',
    },
  }
</script>

<script
  src="http://localhost/embed.min.js"
  id="YOUR_DIFY_APP_TOKEN"
  defer>
</script>

<style>
  #dify-chatbot-bubble-button {
    background-color: #1C64F2 !important;
  }

  #dify-chatbot-bubble-window {
    width: 24rem !important;
    height: 40rem !important;
  }
</style>
```

## 4. 参数说明

### 4.1 `systemVariables.user_id`

必传。

作用：

- 标识第三方当前登录用户
- 用于历史会话隔离
- 不同 `user_id` 之间的历史记录互不串线

建议：

- 使用第三方系统内部稳定唯一 ID
- 不要传昵称、手机号这类可能变化的字段

### 4.2 `inputs.context_token`

必传。

作用：

- 透传到 Workflow / Agent 工具
- 工具可直接读取后调用第三方接口

推荐用法：

- 工具请求头带上 `Authorization: Bearer <context_token>`

### 4.3 `allowNewChat`

建议传 `true`。

作用：

- 允许用户在左侧点击“开启新对话”
- 即使配置了固定 `conversation_id`，也不会锁死在旧会话里

### 4.4 `systemVariables.conversation_id`

可选。

作用：

- 打开指定会话

注意：

- 如果传了固定 `conversation_id`，又希望用户仍能新建对话，需要同时传 `allowNewChat: true`

---

## 5. 工作流 / Agent 侧怎么取值

### 5.1 Start 节点输入变量

建议在应用里定义：

- `context_token`
- `integration_id`

### 5.2 工具中使用

工具可以直接读取：

- `context_token`

常见用法：

```text
Authorization: Bearer {{ context_token }}
```

### 5.3 用户隔离

系统变量里可直接使用：

- `sys.user_id`

## 6. 当前嵌入能力

当前脚本嵌入模式下，第三方业务系统不需要自己再写一套聊天侧边栏逻辑，Dify 内部已支持：

- 左侧历史会话列表
- 新建对话按钮
- 历史对话切换
- 会话消息刷新
- 窗口拖拽和缩放

第三方侧原则上只需要：

1. 注入配置
2. 传入用户 ID
3. 传入 `context_token`

当前状态补充：

- 第三方应用嵌入式对话框已验证可正常使用
- 当前方案已满足基础对话、历史切换和新建会话场景
- 后续需要重点评估：是否在对话框内直接实现 ECharts 图表渲染能力

## 7. 接入建议

建议第三方系统按下面顺序接入：

1. 先打通 `user_id`
   确保会话隔离正确
2. 再打通 `context_token`
   确保工具可调用第三方接口
3. 最后按需增加 `conversation_id`
   仅在需要打开指定会话时再传

---

## 8. 常见问题

### 8.1 为什么必须传 `user_id`

因为嵌入式对话的历史隔离依赖第三方用户标识；不传时，不同访问者可能落在同一个匿名上下文中。

### 8.2 为什么刚发完消息切换会话会丢内容

当前版本已修复该问题。消息完成后会主动刷新当前会话的消息缓存，切回历史会话时会看到最新内容。

### 8.3 业务系统要不要自己实现历史列表

不需要。当前推荐直接用 Dify 内置嵌入聊天 UI。

### 8.4 `context_token` 放前端是否安全

可以先这样落地，但安全性一般。后续建议升级为：

- 前端传短期票据
- 由第三方后端换取真实 token
- Dify 工具调用时走 BFF / Gateway
